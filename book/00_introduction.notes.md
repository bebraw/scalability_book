## Implemented introduction spine

1. Define scalability as maintained valued behavior under pressure.
2. Treat the web application and its development system as connected objects of analysis.
3. State the agentic-web thesis before author context: coding agents raise implementation capacity and shift human attention toward intent, constraints, validation, integration, and ownership.
4. Explain the three fresh implementations as a bounded comparison rather than a universal model ranking.
5. Point course participants to the project introduction, which centralizes submission checkpoints, assistance and acceptance evidence, external contributions, and retained learning outside the main book content.
6. Map each chapter to the evidence or decision it contributes to the final synthesis.

## Secondary teaching intention: from prompting to loops

A hoped-for side effect of the course is that students become able to develop bounded agent loops and need less incessant prompting for routine continuation, checking, and repair.
Keep this as a reminder for teaching, separate from the official learning outcomes, required submissions, and grading criteria.

While discussing the existing project work, ask which recurring prompt could become a maintained instruction, a check, or a rule for continuing, stopping, or escalating.
Use Establish to make the human-guided loop visible, Challenge to notice repeated interventions, and Compare to show how a reusable workflow can take over those routine steps.
Work within each phase's assigned tools and coordination limits; a reusable loop can use one agent.

The desired shift is fewer prompts that merely tell the agent what routine step comes next, while students retain the understanding and judgment to set the goal, challenge the evidence, and accept or redirect the work.
Use the final discussion to revisit that possibility, without adding a new deliverable or treating less human intervention as automatically better.

## Project artifacts

Each chapter should help you produce or revise one concrete project artifact.
By the end of the course, these artifacts should form a small engineering portfolio around your event tracking system:

- Chapter 1: scalability dimensions checklist.
- Chapter 2: README, assumptions, and development process notes.
- Chapter 3: shared measurement protocol and implementation A baseline.
- Chapter 4: architecture reading, implementation A analysis, and an implementation B architecture hypothesis.
- Chapter 5: friction audit.
- Chapter 6: repeated primary pressure, a bounded correctness or recovery case, and an activity-based documented-incident transfer.
- Chapter 7: agent instructions, task boundaries, and review workflow.
- Chapter 8: three-way scaling comparison, target design, and scaling trade-off table.
- Chapter 9: final evidence-based reflection.

## 5 ECTS scope guidance moved from reader content

The complete book is broader than the required reading contract for one course run.
For the nine-lecture, 5 ECTS course, the introduction, three part openings, and nine numbered chapters form the required conceptual path.
The project specifications are working references used while producing evidence.
Case studies and appendices are selected extensions: read one when the instructor assigns it or when it answers a problem the project has reached, not simply because it appears in the book.

The planned 135 hours are divided as follows:

| Activity                                         | Planned time | Scope                                                                                                    |
| ------------------------------------------------ | -----------: | -------------------------------------------------------------------------------------------------------- |
| Lectures or equivalent activities                |     18 hours | Nine two-hour sessions                                                                                   |
| Reading, lecture preparation, and learning diary |     18 hours | Approximately two hours per lecture for the aligned chapter, preparation, and a concise reflective entry |
| Group projects, evidence, and reflection         |     99 hours | Three bounded builds and their cumulative evidence rather than three polished products                   |

Suggested reading contract:

- Required path: the introduction, part openings, and nine numbered chapters.
- Project reference: the common specification, current phase specification, environment sheet, and assessment rubric; consult the relevant sections while working rather than memorizing them.
- Selected extension: case studies, appendices, and optional labs only when assigned or useful to a declared project question.
- The complete PDF is not a cover-to-cover assignment.

The practical ceiling matters as much as the reading path.
The shared event-tracking behavior should stay modest; only one scaling response is implemented and remeasured; and distributed infrastructure, extra product workflows, and broad visual polish are optional.
When the available time becomes tight, reduce optional features and extension reading before weakening acceptance checks, measurement, recovery, review, or reflection.
