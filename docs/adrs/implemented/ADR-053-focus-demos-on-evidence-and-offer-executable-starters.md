# ADR-053: Focus demos on evidence and offer executable starters

**Status:** Implemented

**Date:** 2026-10-23

## Context

The demo review found duplicated workflow instruction, a submission-only widget and planners whose invented coefficients fixed the relationships students should investigate.
The CSV constraint loop described a download check as executed while its download control was disabled.
The course needs concrete reasoning practice and a manageable learning path within its existing 135-hour budget.

## Decision

Retain 29 demos and distinguish main-reading investigations, optional depth and project worksheets in the shared catalog and gallery.
Retire the workflow simulator and signal picker, preserve their useful exercise/questions in the reading and replace the final-reflection widget with a static four-bundle evidence index.
Keep the fleet planner's task-specific scope, permissions, handoffs and packets, and the scaling planner's correctness boundary, alternatives and operating obligations.
Remove their invented cost/time/risk forecasts and relief ratings; actual runs and workloads supply comparative evidence.

Label the constraint loop's candidates and check results as scripted, with no claim that a model, test runner or download action executed when it did not.
Offer a separate optional CSV starter that already renders, filters and handles downloads, leaving one pure serialization function to implement with the learner's model and harness.
Supply a maintained specification, task prompt, decision template, fixed independent contract expectations and actual downloaded-byte checks.
Keep setup preflight separate from the expected unfinished-feature failures, and retain all check results even when one suite fails.
Verify a completed candidate in a disposable copy while distributing the implementation gap.

This adds no required feature, submission or grading criterion.
Use existing practice time and retain optional depth for different capabilities.
Starter code is public synthetic teaching material, independent of the private audit reference and any model credential.

The catalog and resource metadata change together; the three materially changed reading activities advance to version 2.
Retired IDs are removed from current retrieval and live controls; historical notebook sources remain stored and can use the general learning loop.
Browser observation schema and notebook storage versions do not change.

## Trigger

The instructor approved the 32-demo review's cleanup and requested a concrete CSV starter for local model-assisted implementation.

## Alternatives

- Keep every widget and qualify invented scores: retains duplicate interactions and presets the comparison students should test.
- Replace all simulations with live implementation: increases setup and workload, while explicit formal models and bounded mechanism illustrations remain useful.
- Require every local lab: reduces room for independent project work before difficulty has been calibrated.

## Consequences

The reading preserves coverage of architectural mechanisms, formal models and evaluation; actual project work remains responsible for practical build/deployment evidence.
Public resources and preview assets need updating alongside the visible controls.
An intentionally incomplete starter requires explicit documentation of its expected failures and clean-copy verification of the supplied checks.
No learner-outcome improvement is claimed without a learner trial.

## Implementation and verification

Ownership and maintenance are recorded in [the demo guide](../../demo-style-guide.md), [development guide](../../development.md) and [architecture map](../../../ARCHITECTURE.md).
The [starter README](../../../labs/csv-export/README.md) owns setup, scope and expected results; [the student specification](../../../labs/csv-export/SPEC.md) owns CSV behavior.
The affected Chromium interactions, all-demo learning cockpit, gallery themes/accessibility and WebKit observation bridge pass.
Investigation tests reject obsolete activity versions and retain historical notes from retired demos.
A clean-unpacked ZIP installs from its lockfile; a disposable completed candidate passes all seven serialization checks and all three browser cases, including actual downloaded bytes.
The distributed starter retains its implementation gap, passes setup preflight and the browser baseline, and fails the intended feature checks.
An unescaped candidate fails independent contract checks; the scripted demo's false executed-download claim was reproduced before correction.
Production publication and learner difficulty remain separate from repository implementation.
